# 画面遷移図

## 1. ドキュメント概要

- ドキュメント名：画面遷移図
- 対象システム：そなえアレ 食物アレルギー家庭向け防災備蓄支援アプリ
- 目的：
  - 画面間の遷移を明確にし、UI設計・実装・テストの前提をそろえる
  - ユーザーが「家族情報登録 → 備えプラン作成 → 商品確認 → 備蓄登録 → 期限確認 → 通知経由で再確認」まで進める主動線を整理する
- 参照元：
  - PRD確定版
  - 要件定義確定版

---

## 2. 画面遷移図の考え方

本アプリは、食物アレルギー家庭が家族条件に合った“食べられる備え”を迷わず準備し、購入後の備蓄管理や期限確認まで継続できる状態を支援することを目的とする。

そのため、画面遷移は単なる「提案表示」で終わらず、以下の一連の流れが途切れず成立することを重視する。

1. トップ画面でサービス概要を理解する
2. 会員登録 / ログインを行う
3. 家族情報・アレルギー情報を登録する
4. 備えプランを作成し、候補商品を確認する
5. 商品サイトへ遷移して購入する
6. 購入した商品を備蓄品一覧画面で登録する
7. ホームで期限・費用・保存済みプランを確認する
8. 賞味期限30日前の通知メールを受け取る
9. 通知メールから備蓄品一覧画面へ遷移し、期限が近い商品を確認する
10. 必要に応じて保存済みプランや備えプラン詳細を確認し、再購入や削除につなげる

## 6. 主動線の説明

### 6.1 初回利用の主動線

初回ユーザーは、トップ画面から会員登録またはログインを行い、ホームに遷移する。
その後、家族情報登録 / 編集画面で家族構成とアレルギー情報を登録し、備えプラン作成画面で想定日数・候補の範囲・優先方針を入力する。
生成された備えプランは備えプラン詳細画面で確認し、必要に応じて商品サイトへ遷移したり、プランを保存したり、備蓄登録へ進む。

### 6.2 購入後の管理動線

商品購入後は、備蓄品一覧画面で商品名、数量、賞味期限、単価を登録する。
備蓄品一覧画面では、期限が近い商品の表示と登録済み備蓄商品の一覧表示を行い、不要な備蓄商品の削除も可能とする。

### 6.3 継続利用・通知動線

ホームでは、家族情報、コスト概要、期限が近い商品、備蓄品一覧、料金プラン、保存済みプランをまとめて確認できる。
さらに、賞味期限30日前のメール通知を受けたユーザーは、通知メールから備蓄品一覧画面へ遷移し、期限が近い商品を確認し、必要に応じて保存済みプラン一覧や備えプラン詳細を確認して再購入につなげる。

また、保存済みプラン確認時には、備えプラン詳細画面で追加機能としてプラン名・人数・日数を限定的に編集できるようにする。人数・日数を変更した場合は、商品の数量のみを再計算し、更新後の内容を同画面内で保存できるようにする。

## 8. 画面遷移図作成上の補足

本MVPでは、専用の備えプラン編集画面、備蓄商品編集画面、備え見直しページは作成しない。

ただし、備えプラン編集機能は当初MVP対象外として整理していた追加機能として、備えプラン詳細画面（UI-007）に限定的に実装する。編集可能項目はプラン名・人数・日数とし、人数・日数変更時の再計算対象は商品の数量のみとする。

備蓄品は「編集」ではなく、備蓄品一覧画面で登録と削除を行う。

通知導線は専用の見直しページではなく、通知メール → 備蓄品一覧画面 に集約する。

商品購入はアプリ内で完結せず、外部商品サイトへの遷移で行う。

認証必須画面は、未ログイン状態では表示させず、ログイン画面へリダイレクトする。

## 9. この画面遷移図で確認したいこと

- 初回ユーザーが迷わず「登録 → 家族情報入力 → プラン作成 → 商品確認」まで進めるか
- 商品確認後に「購入 → 備蓄登録 → 期限確認」までつながるか
- 通知後に「通知メール → 備蓄品一覧画面 → 必要に応じて保存済みプラン確認・再購入」の流れが成立するか
- 無料 / 有料プランの導線がホームと保存済みプラン一覧から自然につながるか
